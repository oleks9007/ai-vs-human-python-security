MANUAL SECURITY REVIEW PROTOCOL
Each file implements one small Python task (function names describe the task). Files are anonymised (S01-S40).

A scanner warning is a CONFIRMED vulnerability only if ALL hold:
 (a) untrusted input or attacker-controllable state can reach the flagged code,
 (b) no effective mitigation is present elsewhere in the file,
 (c) the weakness maps to a CWE entry.
Otherwise it is a FALSE POSITIVE.

Rule 1. All function parameters are untrusted (supplied by an external user).
Rule 2. For weaknesses that do not depend on input (hard-coded secrets, weak password hash, weak PRNG for security tokens), (a) is met when the weakness affects the security purpose of the code. Hard-coded credentials count even when the literal looks like a placeholder.
Rule 3. Import-only notices (e.g. Bandit B403 import pickle, B404 import subprocess) are false positives; the actual call is judged on its own line.
Rule 4. A request without timeout (CWE-400) is confirmed only when the URL is supplied by the caller.
Rule 5. Unique vulnerabilities: count each CWE at most once per file.
Clarifications:
 C1. Option injection via a host argument starting with "-" (CWE-88) when arguments are passed as a list without shell: not counted.
 C2. Password hashing is adequate if it uses bcrypt, scrypt, Argon2, or PBKDF2-HMAC-SHA256 with >= 600,000 iterations and a random salt.
 C3. Comparing a plain-text password against a database column is not counted when the database schema with a plain password column is given by the task (check_login tasks).
 C4. CWE-20 and CWE-209 are counted only when they lead to a concrete exploitable effect; printing a parser error is not counted.
 C5. Issues outside the checklist below are not counted (you may note them).

MANUAL CHECKLIST (apply to EVERY file, including files without warnings):
 CWE-89: queries use parameters, not string concatenation/formatting.
 CWE-78: no os.system / subprocess with shell=True on user-controlled input.
 CWE-95: eval/exec not applied to input.
 CWE-22: file paths built from a folder plus a user-supplied name (or a user-supplied key) cannot escape the intended directory.
 CWE-916/CWE-256: passwords are hashed adequately (see C2); plain-text storage = CWE-256; fast or unsalted hash = CWE-916.
 CWE-798: no passwords, keys or tokens written in the source.
 CWE-338: security tokens use the secrets module, not random.
 CWE-502: no pickle.load or yaml.load on untrusted data (yaml.safe_load is fine).
 CWE-20, CWE-209: see C4.
 CWE-295: certificate verification not disabled (verify=False).
 CWE-377: temporary files created with the tempfile module, not with predictable names in a shared temporary directory.
 CWE-400: see Rule 4.
